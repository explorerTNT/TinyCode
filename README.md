# TinyCode

**Терминальный AI-агент для маленьких локальных моделей.**
Пишет код, правит файлы, запускает команды — без облака и без API-ключей.

## Что это

TinyCode — агент командной строки, который работает через **локальный OpenAI-совместимый сервер**
(llama.cpp или LM Studio). Ничего не уходит в интернет, ключи не нужны.

Проект заточен под **маленькие модели уровня 2B**, у которых мало здравого смысла и много фантазии.
Отсюда и особенности: автопочинка путей, детект обрезанной генерации, подсказки в текстах ошибок.
Всё это выросло из реальных прогонов, а не из красивой архитектуры.

> [!NOTE]
> Это личный исследовательский проект. Он решает узкую задачу — выяснить, где именно ломается
> 2B-модель в роли кодового агента, и подпереть эти места инструментами.

> [!IMPORTANT]
> Проект переписан с Python на **Go**. Исходная Python-реализация осталась в ветке
> [`legacy/python`](https://github.com/explorerTNT/TinyCode/tree/legacy/python) и больше не развивается.

## Возможности

| | |
|---|---|
| **9 инструментов** | чтение, запись, редактирование, поиск по содержимому и по именам, shell, вопрос пользователю, веб-поиск и загрузка страницы |
| **Plan mode** | сначала read-only анализ и план, затем выполнение по шагам после подтверждения |
| **Сессии** | сохранение, загрузка и продолжение диалога через `/session` и `--resume` |
| **Права доступа** | `auto` / `ask` / `deny` для shell-команд и записи файлов |
| **Управление контекстом** | автоматическая обрезка истории с сохранением пар вызов–результат |
| **Стриминг** | ответ и рассуждения модели видно по мере генерации |
| **TUI** | интерактивный интерфейс на Bubble Tea с автодополнением команд и путей |
| **Упоминания файлов** | `@путь` подставляет содержимое файла в запрос, `@путь#10-40` — только нужные строки |
| **Побочные вопросы** | `/btw` отвечает на снимке истории, не мешая работе основного агента |
| **Бенчмарк** | `cmd/benchmark` замеряет скорость и прохождение задач |

### Подпорки под маленькие модели

Не украшение, а то, без чего 2B не доходит до конца задачи:

- **Автопочинка путей** — модель коверкает путь, агент находит файл по имени и подставляет верный
- **Правка по номерам строк** — `edit_file` принимает `start_line`/`end_line` из `read_file`, что надёжнее поиска по тексту
- **Детект обрезки** — оборванная генерация не записывается на диск как «успешно»
- **Подсказки в ошибках** — вместо «не найдено» показываются реальные строки файла и похожие имена
- **Защита от циклов** — повторные одинаковые вызовы и зацикленные ответы прерываются
- **Песочница** — файловые операции и shell ограничены рабочей директорией
- **Две температуры** — на шагах с вызовом инструментов используется низкая (`action_temperature`),
  на обычном тексте — обычная. Так меньше поломанного JSON в аргументах.

## Быстрый старт

**1. Поднимите локальный сервер.** Например, llama.cpp:

```powershell
llama-server -m model.gguf -c 32768 -ngl 99 --jinja `
             --host 127.0.0.1 --port 8080 --reasoning-format deepseek
```

Флаг `--jinja` обязателен — без него не работает вызов инструментов.

**2. Соберите и запустите агента:**

```powershell
git clone https://github.com/explorerTNT/TinyCode
cd TinyCode
go build -o tiny-code.exe .
.\tiny-code.exe
```

Либо возьмите готовый бинарник со страницы [Releases](https://github.com/explorerTNT/TinyCode/releases) —
там собраны сборки для Windows, Linux и macOS (amd64 / arm64).

При первом запуске создаётся `~/.tinycode/config.json` со значениями по умолчанию.
Рабочая директория не сохраняется в конфиге — по умолчанию используется текущая.

## Использование

```powershell
.\tiny-code.exe                                       # интерактивный режим (TUI)
.\tiny-code.exe "объясни, что делает main.go"          # одиночный запрос
.\tiny-code.exe -workspace C:\project -permission auto "добавь тесты"
.\tiny-code.exe -resume                                # продолжить последнюю сессию
.\tiny-code.exe -resume -session my_session            # продолжить сессию по имени
```

### Команды в сессии

| Команда | Действие |
|---|---|
| `/help` | Список команд |
| `/plan [описание]` | Режим планирования: анализ, план, подтверждение, выполнение |
| `/session save\|load\|list [имя]` | Сохранение, загрузка и список сессий |
| `/sessions` | То же, что `/session list` |
| `/clear` | Очистить историю |
| `/new` | Новая сессия (предыдущая сохраняется) |
| `/compact` | Сжать контекст |
| `/btw <вопрос>` | Побочный вопрос, не прерывая работу агента |
| `/exit` | Выход |
| `! <команда>` | Выполнить shell-команду напрямую |

Автодополнение работает по нечёткому совпадению: `/` открывает меню команд, `@` — меню файлов
(часто упоминаемые поднимаются выше). `@путь#10-40` вставит только строки 10–40.

### Аргументы

| Аргумент | Описание |
|---|---|
| `-workspace <путь>` | Рабочая директория (по умолчанию текущая) |
| `-permission auto\|ask\|deny` | Режим прав (по умолчанию `ask`) |
| `-model <имя>` | Переопределить имя модели |
| `-resume` | Продолжить последнюю сессию |
| `-session <имя>` | Имя сессии для `-resume` (по умолчанию последняя) |
| `-lang en\|ru` | Язык интерфейса |
| `-version` | Показать версию и выйти |

### Конфигурация

Настройки лежат в `~/.tinycode/config.json`. Любое поле можно переопределить
переменной окружения:

| Переменная | По умолчанию |
|---|---|
| `TINYCODE_HOST` | `127.0.0.1` |
| `TINYCODE_PORT` | `1234` |
| `TINYCODE_NAME` | `qwen/qwen3.5-9b` |
| `TINYCODE_PERMISSION_MODE` | `ask` |
| `TINYCODE_WORKSPACE` | текущая директория |
| `TINYCODE_MAX_TOKENS` | `4096` |
| `TINYCODE_SERVER_CONTEXT` | `32768` |
| `TINYCODE_CONTEXT_LIMIT` | `26000` |
| `TINYCODE_MAX_TOOL_ROUNDS` | `50` |
| `TINYCODE_TEMPERATURE` | `0.6` |
| `TINYCODE_ACTION_TEMPERATURE` | `0.1` |

## Требования

- **Go 1.26+** — только для сборки из исходников; готовый бинарник зависимостей не требует
- **Локальный OpenAI-совместимый сервер** — llama.cpp с `--jinja` или LM Studio
- **Модель с поддержкой tool calling** — Qwen, Llama 3.x, Mistral и подобные
- **ripgrep** — необязателен, ускоряет поиск; без него работает встроенный fallback

Разрабатывается и проверяется в первую очередь на **Windows** (shell-слой использует PowerShell,
на остальных системах — `sh`). CI собирает и прогоняет тесты на Windows, Linux и macOS.

Требования к железу зависят только от выбранной модели и бэкенда — TinyCode сам по себе
почти ничего не потребляет.

## Разработка

```powershell
go build ./...            # сборка
go test ./...             # тесты
go vet ./...              # анализатор
gofmt -l .                # проверка форматирования
staticcheck ./...         # линтер (конфиг в staticcheck.conf)
```

### Бенчмарк

```powershell
go run ./cmd/benchmark              # полный прогон
go run ./cmd/benchmark -quick       # только 2 задачи
```

Результаты пишутся в `benchmark_result.json`.

### CI/CD

| Workflow | Триггер | Что делает |
|---|---|---|
| [`ci.yml`](.github/workflows/ci.yml) | push / PR | gofmt, `go vet`, staticcheck, `go mod tidy`, тесты на Windows/Linux/macOS, кросс-сборка на 6 платформ |
| [`release.yml`](.github/workflows/release.yml) | push в `main`, тег `v*`, вручную | считает версию, собирает архивы, `SHA256SUMS.txt`, публикует GitHub Release |

### Автоматические релизы

Версия считается сама по сообщениям коммитов
([Conventional Commits](https://www.conventionalcommits.org/)) с последнего тега:

| Коммиты с последнего тега | Bump | Пример |
|---|---|---|
| `feat!:` или `BREAKING CHANGE` в теле | major | `v1.2.3` → `v2.0.0` |
| `feat:` | minor | `v1.2.3` → `v1.3.0` |
| `fix:` / `perf:` / `refactor:` | patch | `v1.2.3` → `v1.2.4` |
| только `docs:` / `chore:` / `ci:` / `test:` | — | релиз не создаётся |

То есть достаточно писать осмысленные коммиты — тег и релиз появятся сами при пуше в `main`.

Если нужно выпустить версию руками, есть два пути:

```powershell
git tag v0.1.0; git push origin v0.1.0   # явный тег — публикуется как есть
```

либо запустить workflow **Release** через `workflow_dispatch`, выбрав bump
(`auto` / `patch` / `minor` / `major`) — это переопределит автоопределение.

Версия вшивается в бинарник через `-ldflags -X main.version` и доступна как `tiny-code -version`.
Сборки из CI получают версию от `git describe`, поэтому у dev-бинарников она вида `v0.1.0-3-gabc1234`.

## Структура

```
TinyCode/
├── main.go                  # точка входа, флаги CLI
├── cmd/benchmark/           # замер производительности модели
└── internal/
    ├── agent/               # цикл агента, вызовы модели, контекст, сессии, plan mode
    ├── config/              # конфиг (~/.tinycode/config.json) и переменные окружения
    ├── llm/                 # клиент OpenAI-совместимого API
    ├── permissions/         # права на запись и shell
    ├── tui/                 # интерфейс (Bubble Tea), автодополнение, @-упоминания
    └── tools/
        ├── read.go          # чтение (защита от бинарников и огромных файлов)
        ├── write.go         # запись
        ├── edit.go          # точечная правка по номерам строк или по тексту
        ├── grep.go          # поиск по содержимому (ripgrep + fallback)
        ├── glob.go          # поиск по именам (фильтр мусорных папок)
        ├── bash.go          # shell (PowerShell на Windows, sh на остальных)
        ├── ask_user.go      # вопрос пользователю
        ├── web_search.go    # веб-поиск
        └── web_fetch.go     # загрузка страницы
```

## Известные ограничения

Честно о том, что работает плохо:

- **Модели 2B не тянут длинную генерацию.** Практический потолок связного кода за один вызов —
  около 2500–3000 байт. Файл крупнее приходится собирать по частям через `edit_file`.
- **Инструменты работают надёжнее, чем логика.** 2B-модель доводит задачу до конца, но качество
  кода остаётся слабым: дубли, off-by-one, неиспользуемые методы.
- **Reasoning-модели часто уходят в пустое размышление** и возвращают ответ без вызова инструмента.
  Агент это ловит и подталкивает дальше, но раунды тратятся.
- **Тестов мало.** Автотесты есть только для пакета `tui` (автодополнение, нечёткий поиск,
  `@`-упоминания); `agent`, `tools` и `config` проверяются вручную.
- **Проверено в основном на Windows** с llama.cpp. Сборки под Linux и macOS проходят CI,
  но в реальных прогонах обкатаны слабо.
