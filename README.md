# TinyCode

**Терминальный AI-агент для маленьких локальных моделей.**
Пишет код, правит файлы, запускает команды — без облака и без API-ключей.

## Что это

TinyCode — агент командной строки, который работает через **локальный OpenAI-совместимый сервер**
(llama.cpp или LM Studio). Ничего не уходит в интернет, ключи не нужны.

Проект заточен под **маленькие модели уровня 2B**, у которых мало здравого смысла и много фантазии.
Отсюда и особенности: автопочинка путей, детект обрезанной генерации, проверка синтаксиса перед записью
файла и подсказки в текстах ошибок. Всё это выросло из реальных прогонов, а не из красивой архитектуры.

> [!NOTE]
> Это личный исследовательский проект. Он решает узкую задачу — выяснить, где именно ломается
> 2B-модель в роли кодового агента, и подпереть эти места инструментами.

## Возможности

| | |
|---|---|
| **9 инструментов** | чтение, запись, редактирование, поиск по содержимому и по именам, shell, вопрос пользователю, веб-поиск и загрузка страницы |
| **Plan mode** | сначала read-only анализ и план, затем выполнение по шагам после подтверждения |
| **Сессии** | сохранение, загрузка и продолжение диалога через `/session` и `--resume` |
| **Права доступа** | `auto` / `ask` / `deny` для shell-команд и записи файлов |
| **Управление контекстом** | автоматическая обрезка истории с сохранением пар вызов–результат |
| **Стриминг** | ответ и рассуждения модели видно по мере генерации |
| **Бенчмарк** | `benchmark.py` замеряет скорость и прохождение задач |

### Подпорки под маленькие модели

Не украшение, а то, без чего 2B не доходит до конца задачи:

- **Автопочинка путей** — модель коверкает длинный абсолютный путь, агент находит файл по имени и подставляет верный
- **Детект обрезки** — оборванная генерация не записывается на диск как «успешно»
- **Проверка синтаксиса** — битый Python-файл не сохраняется, модель сразу получает номер строки с ошибкой
- **Подсказки в ошибках** — вместо «не найдено» показываются реальные строки файла и похожие имена
- **Защита от циклов** — повторные одинаковые вызовы и зацикленные ответы прерываются
- **Windows-первый** — PowerShell вместо bash, `python` вместо `python3`, никаких `/dev/null`

## Быстрый старт

**1. Поднимите локальный сервер.** Например, llama.cpp:

```powershell
llama-server -m model.gguf -c 32768 -ngl 99 --jinja `
             --host 127.0.0.1 --port 8080 --reasoning-format deepseek
```

Флаг `--jinja` обязателен — без него не работает вызов инструментов.

**2. Запустите агента:**

```powershell
git clone https://github.com/explorerTNT/TinyCode
cd TinyCode
.\run.ps1
```

`run.ps1` сам создаст виртуальное окружение и поставит зависимости.

## Использование

```powershell
.\run.ps1                                    # интерактивный режим
.\run.ps1 "объясни, что делает main.py"      # одиночный запрос
.\run.ps1 -workspace C:\project -permission auto "добавь тесты"
```

### Команды в сессии

| Команда | Действие |
|---|---|
| `/plan [описание]` | Режим планирования: анализ, план, подтверждение, выполнение |
| `/session` | Сохранение, загрузка и список сессий |
| `/clear` | Очистить историю |
| `/compact` | Сжать контекст, оставив последний обмен |
| `/exit` | Выход |
| `! <команда>` | Выполнить shell-команду напрямую |

### Аргументы

| Аргумент | Описание |
|---|---|
| `--workspace <путь>` | Рабочая директория (по умолчанию текущая) |
| `--permission auto\|ask\|deny` | Режим прав (по умолчанию `ask`) |
| `--model <имя>` | Переопределить имя модели |
| `--resume [имя]` | Продолжить последнюю или названную сессию |

### Переменные окружения

| Переменная | По умолчанию |
|---|---|
| `LMSTUDIO_HOST` | `127.0.0.1` |
| `LMSTUDIO_PORT` | `8080` |
| `TINY_CODE_MODEL` | `qwen3.5-2b` |
| `TINY_CODE_PERMISSION` | `ask` |
| `TINY_CODE_MAX_ROUNDS` | `50` |
| `TINY_CODE_TEMPERATURE` | `0.6` |
| `TINY_CODE_ACTION_TEMPERATURE` | `0.1` |
| `TINY_CODE_ASK_USER` | — (авто-ответ на вопросы, для тестов) |

Две температуры не опечатка: на шагах с вызовом инструментов используется низкая
(`action_temperature`), на обычном тексте — обычная. Так меньше поломанного JSON в аргументах.

## Требования

- **Python 3.10+** (используется синтаксис `str | None`)
- **Локальный OpenAI-совместимый сервер** — llama.cpp с `--jinja` или LM Studio
- **Модель с поддержкой tool calling** — Qwen, Llama 3.x, Mistral и подобные
- **Windows** — на macOS и Linux не проверялось; shell-слой ориентирован на PowerShell
- **ripgrep** — необязателен, ускоряет поиск; без него работает встроенный fallback

Требования к железу зависят только от выбранной модели и бэкенда — TinyCode сам по себе
почти ничего не потребляет.

## Структура

```
TinyCode/
├── agent.py           # цикл агента, вызовы модели, работа с контекстом
├── config.py          # настройки и переменные окружения
├── system_prompt.py   # системный промпт и промпт plan mode

├── permissions.py     # права на запись и shell
├── benchmark.py       # замер производительности
├── run.ps1            # запуск с автосозданием venv
└── tools/
    ├── read.py        # чтение (защита от бинарников и огромных файлов)
    ├── write.py       # запись (проверка синтаксиса, LF-переводы строк)
    ├── edit.py        # точечная правка (подсказки при промахе, CRLF-совместимость)
    ├── grep.py        # поиск по содержимому (ripgrep + fallback)
    ├── glob.py        # поиск по именам (фильтр мусорных папок)
    ├── bash.py        # shell (нормализация Linux-команд под Windows)
    ├── ask_user.py    # вопрос пользователю
    ├── web_search.py  # веб-поиск
    └── web_fetch.py   # загрузка страницы
```

## Известные ограничения

Честно о том, что работает плохо:

- **Модели 2B не тянут длинную генерацию.** Практический потолок связного кода за один вызов —
  около 2500–3000 байт. Файл крупнее приходится собирать по частям через `edit_file`.
- **Reasoning-модели часто уходят в пустое размышление** и возвращают ответ без вызова инструмента.
  Агент это ловит и подталкивает дальше, но раунды тратятся.
- **Проверено только на Windows** с llama.cpp.
- **Веб-инструменты** зависят от `duckduckgo_search`, который переименован в `ddgs` и выдаёт
  предупреждение при импорте (игнорим).
